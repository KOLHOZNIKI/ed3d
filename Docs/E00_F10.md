# E00 F10 body and clothing on a shared skeleton

The project-owned fixture is a simple torso and a separate garment bound to one hierarchy, `Pelvis → Spine → Chest`. The two meshes have separate skin deformers, different blend weights and different mesh bind transforms. The garment is offset by 62.5 mm along Y and 15.625 mm along Z. Each mesh uses all three bones with up to two nonzero influences per point. The authored one-second `SharedTorsoBend` clip rotates `Spine` and `Chest` in different directions. ## Import and export

The first browser import reported six bones for the source's three unique FBX bone nodes. Three.js created a new bone for each cluster reference and nested the duplicate under the preceding copy. The pinned FBXLoader patch now creates one bone per FBX model node and links the cluster references to it. Each skin keeps its own bind and inverse bind matrices. Chrome exported through **Export FBX ZIP** and reopened the result as two meshes, 124 triangles, three bones, and one clip. [Three.js patch](../patches/three+0.187.0.patch)

## Shared bindings and deformation

ufbx 0.23.0 confirmed that both mesh deformers point to the same three FBX bone nodes in the original and export and that their parent links match the fixture. Both files retained every raw cluster control-point index and weight, the per-mesh binding matrices, positions, and triangle connectivity. In Unity, both `SkinnedMeshRenderer` components referenced the same `Transform` objects and the same `rootBone`. The two Unity versions measured zero weight, bind matrix and rest position differences.

Both probes sampled 21 times over the one-second clip, including the keyed extrema at 0.25 s and 0.75 s. Each mesh changed shape in the source, measured by the changing distance between its vertices. The table compares exported world-space positions with the original at the same times.

| Mesh | Source shape change, ufbx | Maximum ufbx error | Maximum Unity 2022.3.62f2 and 6000.3.9f1 error |
| --- | ---: | ---: | ---: |
| Body | 0.1559 m | `3.38e-8 m` | `1.33e-7 m` |
| Clothing | 0.1652 m | `3.18e-8 m` | `2.81e-7 m` |

Unity used Generic rig, imported normals, calculated MikkTSpace tangents, standard skin weights and file scale. Mesh and animation compression and mesh optimization were disabled. This F10 check covers shared bindings and playback over a no-op round-trip. Moving a joint and undoing the change is assigned to the later rig workflow in AT-21. ## Reproduce on Windows

Install the pinned browser probe dependency and build the native reader using the [FBX round-trip setup](E00_FBX_Round_Trip.md#reproduce-on-windows). The full F10 check uses the tracked source and needs no Tripo inputs. The generator optionally regenerates a byte-identical source in `test-results/e00/f10/`.

```powershell
$chrome = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
npm.cmd ci
npm.cmd install --prefix test-results/e00-browser --save-exact playwright-core@1.65.1
npm.cmd run build
node tools/e00/browser.mjs --shared-skin $chrome
$version = '2022.3.62f2' # Repeat with 6000.3.9f1.
$project = python tools/e00/fixtures.py --shared-skin $version
$editor = "C:/Program Files/Unity/Hub/Editor/$version/Editor/Unity.exe"
$log = Join-Path $project 'shared-skin-unity.log'
$unityArgs = @('-batchmode', '-nographics', '-quit', '-projectPath', ('"' + $project + '"'),
  '-executeMethod', 'SharedSkinProbe.Run', '-logFile', ('"' + $log + '"'))
$unity = Start-Process -FilePath $editor -ArgumentList $unityArgs -WindowStyle Hidden -PassThru
$unity.WaitForExit()
if ($unity.ExitCode -ne 0) { throw "Unity probe failed. See $log" }
Get-Content (Join-Path $project 'shared-skin-report.json')
$output = Join-Path $project 'Assets/Fixtures/shared-skin/exported/shared_skin_e00.fbx'
& 'test-results/e00/ufbx/inspect_fbx.exe' tools/e00/fixtures/shared_skin.fbx $output --shared-skin
if ($LASTEXITCODE -ne 0) { throw 'The independent F10 check failed.' }
```

Chrome writes `test-results/e00/exports/shared_skin_e00.zip`. The independent JSON report and the FBX extracted for this run are in `test-results/e00/f10/`. Each generated Unity project contains its own `shared-skin-report.json`.
