# E05 Basic Repair

Repair identifies polygon boundaries by authored connectivity and shows them in the viewport and in a list. Boundary IDs use the lowest vertex ID of the component in the current mesh. The list reports edge count, perimeter, diameter, deviation from the estimated plane, and the reason a contour is ineligible. A connected FBX UV seam with two incident polygons stays outside the boundary list. Unjoined coincident edges are reported as ambiguous.

## Workflow

1. Open **Repair** and select a mesh. Select contours in the list or click their lines in the viewport. Shift-click adds to the selection.
2. Use **Keep Open** for intentional openings. A valid authored GLB `protectedLoop` hint starts protected. Explicit choices are undoable and persist in `.assetfixer`.
3. Select **Planar Fill** for a nearly planar loop or **Fan Fill** to add an interior center. The Fan center can be set in mesh-local coordinates and must see every boundary edge in the projection. **Manual Face** opens the ordered contour in Mesh Edit.
4. In **Auto Fill**, set the scope, edge or diameter limit, planarity tolerance, and allowed methods. Review the colored wireframe and per-contour results. Apply records the entire accepted batch as one Undo entry.
5. Use **Select new faces** to open the patch selection in Mesh Edit. **Paint new faces** scopes the 3D brush to the new faces on an eligible Base Color binding when the patch has projected UVs.

Planar Fill estimates a local plane and triangulates concave contours using the existing boundary vertices. Fan Fill adds a center and interpolates vertex color, supported morph attributes, and normalized skin weights from the boundary. Patches inherit the most frequent adjacent material unless a slot is chosen. The original faces, corner attributes and weights remain intact.

Patch validation checks winding, area, boundary coverage, and intersections with the existing triangles in the patch bounds. A shared topological vertex or edge permits the normal contact at a join. An independent intersection, a collapsed triangle, or an incompatible boundary produces a skip reason. Manual Face uses the same collision check.

New patch faces have no source texture. UV projection assigns local 0–1 coordinates and can reuse existing texels. The default preserves GLB rim tuples where possible and marks new faces for UV review. Project files use schema 5 and retain the repair command and Keep Open choices. Schemas 1–4 remain readable.

## Verification

| --- | --- |
| F04 bottle GLB | The browser found two triangular defects and one protected 12-edge mouth. Object-scope Auto Fill closed both defects in one Undo entry. Single-contour scope and a diameter limit skipped the other defects as requested. Keep Open persisted after reopening. The independent parser and GLB reimport found exactly the original mouth edges as the only open boundary. |
| F03 concave contour | Planar Fill generated six triangles with no new boundary vertices. The patch area matched the contour area at 2.425 square mesh units. The independent parser found no crossing or exterior diagonal. |
| F03 non-planar contour | Planar Fill refused the contour at the default tolerance. Fan Fill rejected an exterior center and accepted an adjusted center. Eight triangles closed the loop, reusing all original vertices and attributes. |
| Invalid geometry | The core probe rejected a cap crossing an existing triangle, coincident unjoined rims, branching edges, a crossing contour, and a Manual Face covering a triangulated sheet. A separate browser fixture verified that the closed FBX cube's UV seams produced zero boundaries. |
| Static bottle FBX | Auto Fill closed two defects and kept the 12-edge mouth. Unity imported 106 triangles and resolved the same Base Color. ufbx matched the original control points, polygon indices, corner UVs and normals, including the authored seam. |
| Animated bottle FBX | Fan Fill closed one selected defect and retained the other defect and mouth. The center received weights 5/6 Base and 1/6 Neck. Unity and ufbx sampled the original clip in 21 positions. Unity's maximum original-vertex pose delta was 0.000000246 m. The new center followed the expected skin deformation within 0.000000068 m. |

The browser used Chrome 158.0.8127.37 with outside requests blocked. The glTF validator reported zero errors and zero warnings for both GLB exports. FBX validation used Unity 2022.3.62f2, Unity 6000.3.9f1, and ufbx 0.23.0. F03, F04, F16 and the seam cube are project fixtures in the repository. The FBX bottle variants are generated by the project-owned fixture script.

## Limits

- Repair operates on a mesh in the base pose. Topology editing requires discarding any active generated atlas first. E06 owns appearance transfer to a new layout.
- Collision checking covers the selected mesh and the patches accepted earlier in the same operation. Separate scene objects fall outside that check.
- Branching, non-manifold and ambiguous components are excluded. The simple contour triangulator supports up to 1,024 boundary vertices. Larger diameters are approximate in the diagnostic list.
- GLB projection can require separate render indices for new corner attributes. The default rim tuples preserve indexed closure when the rim has compatible attributes. A skinned GLB Fan center that requires more than four influences is refused with an explanation.
- Smooth, Grid and Bridge integration follows in E08. This stage covers Planar, Fan and Manual Face.

## Reproduce

```powershell
$chrome = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
npm.cmd run build
npm.cmd run build:debug
node tools/e05-core.mjs
node tools/e05-fixture.mjs
node tools/e05-browser.mjs $chrome
python -B tools/e05-inspect-glb.py tools/e00/fixtures/corpus test-results/e05
$project = python -B tools/e05-unity.py 2022.3.62f2
```

Run the assembled Unity project in batch mode with `-executeMethod E05Probe.Run`. Build the [ufbx inspector](E00_FBX_Round_Trip.md#reproduce-on-windows) and pass `--e05` followed by the FBX files from **bottle**, **bottle-repaired**, **skinned-bottle** and **skinned-bottle-repaired**, in that order. Reports and exported fixtures are in `test-results/e05`.
