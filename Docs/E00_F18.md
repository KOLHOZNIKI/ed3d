# E00 F18 heavy asset and Undo history

## Workload

Both project-owned fixtures use the same static, slightly curved grid with 250,000 triangles and 125,751 control points. The geometry and procedural PNGs are generated locally under the repository's MIT license. The generator is stored in Git. It produces the input archives on demand. The paint fixture exercises the current E00 brush, which accepts one opaque Base Color material. Each cycle imports the model, generates UV1, rebakes Base Color, exports the unpainted checkpoint, draws 24 strokes in six colors, then issues Undo 24 times and closes the model. The probe exports at depths 0, 8, 16 and 24 on the way forward and 16, 8 and 0 on the way back. The second profile imports, unwraps, rebakes all four maps, exports, and closes. Both run through the production build at a 1920 × 1080 drawing buffer and DPR 1. [Memory harness](../tools/e00/memory-browser.mjs) · [History probe](../tools/e00/f18-history.mjs)

## Measurement method

The Windows sampler sums private committed bytes and working-set bytes from the isolated Chrome process tree, including the renderer and GPU process. It requests a sample every 20 ms. The working-set sum can count shared pages more than once. Dedicated GPU VRAM and transients between samples are outside these counters. Each checkpoint memory snapshot is taken one second after its edit and before its export. Each close snapshot is taken after 2.5 seconds. The page collects garbage before the empty baseline and after the last natural close, with a further 20-second idle snapshot. Intermediate cycles use automatic collection. The harness records per-action peaks and latency from the UI operation through completion. The browser saves the last cycle's checkpoint ZIPs for independent verification, and the memory harness and PNG hashing run outside the measured process tree. [Typical-model method](E00_Memory.md#measurement-method)

The host uses Windows 11 Pro build 26300, a Ryzen 9 9950X3D (16 cores, 32 threads), 61.58 GiB of usable system RAM and Chrome 158.0.8127.37. WebGL2 uses an RTX 3070 via ANGLE D3D11, driver 32.0.16.2124. xatlas generated a single 787 × 1035 chart. The bake output and the edited Base Color were both 1574 × 2070. The 4096 × 4096 dimensions apply to the input PNGs.

## Reproduce on Windows

Use installed Chrome and Python and the [pinned browser probe setup](E00_FBX_Round_Trip.md#reproduce-on-windows). Run the profiles sequentially so their working sets do not compete.

```powershell
$chrome = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
npm.cmd ci
npm.cmd run build
node tools/e00/memory-fixture.mjs --heavy-paint
node tools/e00/memory-fixture.mjs --heavy-bake
node tools/e00/memory-browser.mjs test-results/e00/memory/f18_paint.zip $chrome --history-strokes 24 --cycles 3 --label f18-history --idle-seconds 20
node tools/e00/memory-browser.mjs test-results/e00/memory/f18_four_maps.zip $chrome --cycles 3 --label f18-four-maps --idle-seconds 20
```

The archives, reports and raw samples are under `test-results/e00/memory/`. Checkpoint ZIP names have the form `f18-history-paint-00.zip` or `f18-history-undo-00.zip`. The four-map profile writes `f18-four-maps-export.zip`. For independent FBX verification, unpack the input and checkpoint separately and use `inspect_fbx <input.fbx> <output.fbx> --baked <output/uv-atlas-source-corners.bin>`. [Build the independent reader](E00_FBX_Round_Trip.md#reproduce-on-windows)
