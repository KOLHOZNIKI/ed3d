# E00 F13 five skin influences and multiple morph targets

F13 contains a six-point skinned strip with five bones and four triangles. Control points 2 and 3 each have the source weights `(0.3125, 0.25, 0.1875, 0.15625, 0.09375)` for `Joint1` through `Joint5`. The one-second `FifthInfluenceBend` clip moves only `Joint5`, so it exercises the weakest influence on those points. The combined fixture adds two position morphs, `Raise` and `Widen`. The control fixture uses the same mesh, skin and clip and omits the morph channels. [Fixture generator](../tools/e00/adverse-skin-fixture.mjs) · [Repository license](../LICENSE)

## Import and export behavior

The pinned FBXLoader patch counts nonzero source weights per control point before creating the four-slot render attributes. The browser reports an approximate preview, two control points above the limit and a maximum of five. The preview uses and normalizes the four strongest weights. The raw FBX cluster data retains all five weights, and the source-topology exporter writes those original clusters. The successful ZIP includes the preview limit and source counts in `manifest.json`. [Three.js patch](../patches/three+0.187.0.patch)

Chrome opened the combined fixture and the probe matched every imported `Raise` and `Widen` position delta against its expected control point. The interface reports both morph channels on import and identifies the FBX export block. Clicking **Export FBX ZIP** explains that the current exporter cannot preserve the morph targets. The probe observed zero download events and the model remained open. The tracked source FBX retains its original bytes. [Browser probe](../tools/e00/browser.mjs)

Explicit weight reduction and the editing workflow remain assigned to the later weight stage. FBX export of the combined fixture is deliberately blocked. ## Reproduce on Windows

Install the pinned browser harness and compile the independent reader using the [FBX round-trip setup](E00_FBX_Round_Trip.md#reproduce-on-windows). This probe uses the two tracked source files. The generator can reproduce them under `test-results/e00/f13/`.

```powershell
$chrome = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
npm.cmd ci
npm.cmd install --prefix test-results/e00-browser --save-exact playwright-core@1.65.1
npm.cmd run build
node tools/e00/browser.mjs --adverse-skin $chrome
$version = '2022.3.62f2' # Repeat with 6000.3.9f1.
$project = python tools/e00/fixtures.py --adverse-skin $version
$editor = "C:/Program Files/Unity/Hub/Editor/$version/Editor/Unity.exe"
$log = Join-Path $project 'adverse-skin-unity.log'
$unityArgs = @('-batchmode', '-nographics', '-quit', '-projectPath', ('"' + $project + '"'),
  '-executeMethod', 'AdverseSkinProbe.Run', '-logFile', ('"' + $log + '"'))
$unity = Start-Process -FilePath $editor -ArgumentList $unityArgs -WindowStyle Hidden -PassThru
$unity.WaitForExit()
if ($unity.ExitCode -ne 0) { throw "Unity probe failed. See $log" }
Get-Content (Join-Path $project 'adverse-skin-report.json')
$inspect = 'test-results/e00/ufbx/inspect_fbx.exe'
$output = Join-Path $project 'Assets/Fixtures/adverse-skin/exported/f13_wide_skin_e00.fbx'
& $inspect --f13-source tools/e00/fixtures/f13_wide_skin_morphs.fbx
if ($LASTEXITCODE -ne 0) { throw 'The combined source check failed.' }
& $inspect --f13-source $output
if ($LASTEXITCODE -ne 0) { throw 'The exported influence check failed.' }
& $inspect tools/e00/fixtures/f13_wide_skin.fbx $output
if ($LASTEXITCODE -ne 0) { throw 'The control round-trip failed.' }
```

The control export is `test-results/e00/exports/f13_wide_skin_e00.zip`. The FBX tested from that ZIP has SHA-256 `1d5006aa21915ab893e52cee1fa9c157519f01fe816c4423cbf81ef34b54ba93`. Browser and ufbx evidence is under `test-results/e00/f13/`, and each generated Unity project has its own `adverse-skin-report.json`.
